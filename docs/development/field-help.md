# 字段说明与覆盖检查

设置标题左侧的信息按钮展示用途、行为、填写示例和核对来源。普通字段与开关均保留独立的说明按钮，整行仍可进入编辑；只读项也能查看说明。卡片只展示简短摘要，详细内容放在说明弹窗中。

## 覆盖范围

当前清单包含 **671 个配置、状态字段键及兼容别名**，每个键都有中文与英文说明、示例和来源索引。这个数字不是 671 个互不重复的功能，也不是所有第三方插件的字段总数。数据基于 [AstrBot 固定源码版本](https://github.com/AstrBotDevs/AstrBot/commit/6b10af75e118714335aff3aab047bf7689fa1388)。

服务器的新说明优先于旧的内置说明。没有可核实文档的第三方字段会明确标示说明缺失，并保留服务器返回的原文、类型、默认值和约束；客户端不会根据名称猜测未知插件的业务行为。未来服务器新增字段需补入清单并审核含义，才能计入内置覆盖率。

## 阅读与填写

- 示例展示结构，不会自动写入配置。凭据使用占位符，资源标识需换成实际存在的 ID。
- 群聊标识按平台与具体配置决定。通过 `/sid` 查询；例如 `aiocqhttp:GroupMessage:123456789`，不能统一添加 `group:`。
- 当前源码中，空白名单不拦截消息，管理员和 WebChat 还有各自的豁免规则。
- `provider_settings.provider_pool` 尚未实际使用；`default_kb_collection` 是旧字段，不能据此假定所有新旧版本具有相同行为。
- 旧状态字段 `memory.process` 和 `memory.system` 的单位是 MiB；后者表示系统总量。时间戳按手机时区显示。

## 维护说明

`scripts/dev/help-source.json` 是经过核对的上游说明、默认值、文档段落和消费者位置快照。`scripts/dev/help-authored.json` 保存补充解释与纠错，`scripts/dev/field-names.json` 保存中英文标题。更新来源时需要核对真实消费者及兼容差异，不能只复制字段类型。

运行 `python3 scripts/build_locales.py` 同时生成翻译和说明。`python3 scripts/check_repository.py` 会重新生成并比对，缺少解释、英文副本或生成文件过期均使检查失败。Node 测试检查完整清单、示例、父级匹配、未知字段处理及数据保真；JVM 测试通过真实 Rhino 加载器加载说明模块；设备测试检查独立触摸区域与固定色板。

说明位于签名脚本核心中，兼容架构可直接更新核心；每次发布的完整 APK 也包含同一份数据。
