# 脚本核心与架构版本

应用分为 Android 架构层和 JavaScript 业务核心。每个发布版本始终包含可独立安装的完整 APK，并随包携带当次提交的脚本与中英文数据，不需要首次联网下载核心。

## 更新规则

架构指纹由原生 Java、Manifest、资源、构建配置和 Gradle wrapper 计算。JavaScript 与翻译/字段数据不参与指纹。指纹相同且核心版本递增时，应用下载 Release 中的 `core-<版本>.json`，验证后重新加载界面，无需重新安装 APK；指纹不同则下载 APK，经系统安装确认后升级。核心版本采用 Quality 工作流运行号，APK 的 versionCode 也采用同一运行号。切换更新渠道不会降级。

核心包签名使用 APK 的同一个持久 RSA 私钥（SHA256withRSA）。客户端从已安装 APK 的签名证书获取公钥验证，架构与版本号都包含在签名内容中。网络哈希不能代替签名。签名错误、版本倒退、架构不符或脚本验证失败均停止激活。不要在应用内嵌入 GitHub Token；从公开 Release 拉取已通过 CI 的核心。

## 核心边界

`app/src/main/assets/core/main.js` 包含接口路径和载荷规则、响应列表适配、OpenAPI 参数生成、字段元数据遍历、默认值、草稿差异、输入辅助与敏感字段处理。`locales.json` 和 `fields.json` 是可随核心更新的双语界面文案、内置操作名称和字段说明。Android 层保留原生控件、生命周期、网络、认证、加密存储、精确数值校验、文件访问、签名与更新安装。

`CoreRuntime` 通过纯 JSON 调用 `dispatch(name, json)`；内置 Rhino 仅解释执行，不生成 DEX，不提供 Java 包、文件系统或网络桥接，并限制指令执行时间。脚本只能返回数据，实际网络请求仍经过原生的同实例鉴权边界。超出 JavaScript 精确范围的数值使用内部封装跨边界保留，避免群号等配置数值被截断。

新增业务调用需在 `Core.invoke` 中注册，并保持现有 JSON 契约。新增原生能力、修改桥接方法或 Android 权限属于架构更新。客户端扩展仍为声明式 JSON，不允许未签名第三方脚本替换应用核心。

## 回退与排查

核心包先写入原子存储，下次加载才生效；保留上一代核心。「应用更新 → 回退核心」可恢复上一代，或恢复 APK 内置核心。新核心首次启动尚未成功进入主页即崩溃时，下次启动自动回退。损坏或不兼容的磁盘核心会被拒绝并使用内置核心。回退不会删除连接、密码或预设。

测试覆盖原有 JVM 契约、脚本行为、签名篡改、架构不符、版本回退、精确数值、语言/配色偏好，以及 Android 文件分享权限。实际服务器权限不足仍由服务器决定：运行统计需要 `system`，插件接口通常需要 `plugin`。客户端只在读取 404/405 时兼容旧接口，不绕过 403，也不重试写入。
